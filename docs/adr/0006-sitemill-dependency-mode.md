# ADR 0006: sitemill への依存は今フェーズだけ editable なパス依存にする

- ステータス: 採用（2026-09-10）

## 背景
sitemill と akiya-atlas を同時に立ち上げるため、エンジンの変更を即座に反映したい。ただし長期的にはエンジンの版を固定しないと、エンジン側の変更でサイト生成が予告なく変わる。

## 決定
- 今フェーズ: `pyproject.toml` の `[tool.uv.sources]` で `../sitemill` を editable 指定。CI でも両リポジトリを隣に checkout する
- エンジンが安定したら（目安: 3 サービスめが載る前、または初回本番デプロイ後）、`sitemill = { git = "...", tag = "vX.Y.Z" }` のタグ固定に切り替え、更新は明示的な PR で行う
- 切り替え時は ADR を追記し、CI の checkout 手順も同時に直す

## 影響
- エンジンの破壊的変更は、切り替え後は akiya-atlas 側で版上げの判断が要る

## 追記: CI をタグ固定に切り替えた（2026-09-12）

- sitemill に `v0.1.0` を打ち、**akiya-atlas の CI 3 本（`pipeline.yml` / `checks.yml` / `weekly.yml`）が
  そのタグを checkout する**ようにした。sitemill の main の変更は自動では反映されない。
- 理由: sitemill の main で別サービス向けの拡張を始めるため、空き家の日次実行を固定版から切り離す。
  日次は毎晩 270 近い自治体サイトを触るので、エンジンの変更が予告なく入る状態は避ける。
- **手元の開発は path 依存（`../sitemill` の editable）のまま**にした。エンジンとサービスを往復しながら
  直す作業がまだ多く、ここを固定すると手数が増える。その代わり「手元で通っても CI で通らない」ことが
  起こり得るので、エンジンを触ったときは必ずタグを上げてから CI を確認する。
- 版を上げる手順と版の付け方は `docs/runbook/operations.md` の 5 章に置いた。
- `pyproject.toml` の依存はまだ path のまま。ここをタグ固定にするのは、手元でもエンジンを固定したく
  なったとき（3 サービスめが載る頃）に判断する。
