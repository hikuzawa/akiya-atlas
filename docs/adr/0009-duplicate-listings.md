# 0009. 同じ物件が複数の source に出るときの扱い

状態: 提案（2026-09-12）。実装は未着手。

## 背景

全国 270 自治体を巡回した結果、同じ物件が 2 か所に出る形が確認できる。

- **県の横断サイトと市町村サイト**: 長野県の「楽園信州」、佐久市の `39ijyu.com` のように、県や
  広域団体がまとめて載せる一覧と、市町村自身の一覧に同じ物件が出る。
- **市町村サイトの中の重複**: 一覧ページと詳細ページ、地域別のページと全件ページ。
- **成約済みの再掲**: 募集終了後も一覧に残り、別番号で再登録される。

掲載件数は信頼シグナル（数字の帯・都道府県ページ・トップ）に出しているので、重複で膨らむと
「確認できた件数」という約束が崩れる。**重複を数えない**ことを先に決める。

## 1. 決定: 同一物件とみなす条件

次のいずれかを満たすとき、同じ物件とみなす。

1. **物件番号が一致**（`normalize_listing_no` 後）し、**市町村コードが同じ**
2. 物件番号が一致しないが、**所在地・価格・延床面積がすべて一致**し、市町村コードが同じ
   （所在地は番地を落とした「市町村＋大字」まで。価格は円単位、面積は 0.1 ㎡ まで）

2 の条件は「3 つとも値が取れている」ときだけ使う。1 つでも欠けていたら別物件として扱う
（推測で束ねない。ADR 0004 の quote-then-parse と同じ考え方）。

## 2. 決定: どちらを正とするか

**市町村サイトを正**とする。理由は、運営主体が自治体であることが確認済みで（ADR 0007）、
更新が早く、一次情報として案内すべき先だから。

- 市町村サイト由来のレコードを残し、横断サイト由来は隠す（削除はしない）。
- 隠した側は `duplicate_of: <record_id>` を持ち、`status` は変えない。次回の巡回で
  市町村側が消えたら、横断サイト側を表に戻せるようにする。
- 物件ページは正のレコードだけを作る。横断サイトへのリンクは「他のサイトにも掲載」として
  市町村ページの外部リンクに出す（すでにある `external_links` の枠）。

## 3. 決定: どこで判定するか

- 判定は **ビルド前の finalize**（`service.finalize`）で行う。巡回・抽出は source ごとに独立させ、
  横断的な突き合わせは全レコードが揃ってから 1 回だけ行う。
- 判定結果は `data/records/*.jsonl` に書き戻す（`duplicate_of`）。再現できるよう、
  判定に使った条件も `duplicate_reason`（`listing_no` / `address_price_area`）として残す。
- 件数（信頼シグナル・検索索引・数字の帯）は `duplicate_of` が無いレコードだけを数える。

## 4. 決定: 計測する

重複の件数は実行レポートに残す（`stages.finalize.duplicates`）。週次まとめに出し、
条件 2 が効きすぎていないか（別物件を束ねていないか）を見る。

## 5. 代替案と却下の理由

- **横断サイトを巡回しない**: 市町村サイトに一覧が無く横断サイトにしか載らない自治体（相互リンクで
  運営主体を確認済み）が取れなくなる。却下。
- **重複をそのまま出す**: 件数が信頼シグナルなので、膨らむと約束が崩れる。却下。
- **レコードを統合して 1 件にまとめる**: 引用と出典が混ざり、どのページの記載か追えなくなる。
  隠すだけにして、出典は 1 件 1 ページのまま保つ。
