# ADR 0010: 広告の掲載場所・ASP 規約の検査・クリックの計測

- ステータス: 採用（2026-09-12）
- 関連: ADR 0004（所有者向けページとアフィリエイト導線）の「契約後は `/go/<offer>` 経由」を具体化する

## 背景

A8.net で最初の案件（解体工事110番、シェアリングテクノロジー株式会社）が承認された。
今後、査定（複数社）・空き家買取・遺品整理・リフォームが続く見込みで、案件が増えるたびに
「どこに置くか」「規約を満たしているか」を人が思い出すやり方は保たない。
また `/go/<offer>` の 302 はページが読み込まれないため、どのページのどの文脈から押されたかを
後から数える手立てが無かった。

## 決定

### 1. 掲載場所は枠（placement）として宣言する

枠は「ページ × 文脈 × 置ける種別」。案件は置かれる枠を宣言し、テンプレートは枠を描画するだけにする。

| 枠 | 場所 | 置ける種別 |
|---|---|---|
| `owners-consult` | `/owners/` の「相談先」 | すべて（1 種別 1 枠） |
| `owners-flow-sale` | `/owners/` 「売却・賃貸までの流れ」の直後 | 査定・買取 |
| `owners-flow-demolition` | `/owners/` 「解体までの流れ」の直後 | 解体 |
| `owners-cleanup` | `/owners/` 「6 つの選択肢」の片づけの文脈 | 片付け・遺品整理 |
| `owners-renovation` | `/owners/` 「6 つの選択肢」の住む・貸すの文脈 | リフォーム |

- **物件ページ・市町村ページ・トップには広告を置かない**。読み手が購入・入居を検討する人で、
  所有者向けの広告は文脈が合わない。所有者向けの導線は `/owners/` へのテキストリンクに集約する。
  広告リンクが無いので、これらのページには広告表記も出さない
- 同じ種別に複数社が承認された場合、**既定は `rank` の小さい 1 社だけを出す**。
  一括査定・一括見積は商品自体が「複数社比較」なので、同種を並べても選択の負荷が増えるだけで、
  クリックが割れて比較もできなくなる。静的サイトではローテーションも配置時点で固定されるため採らない。
  例外は対応エリアや対象物件が補完関係にある場合に限り 2 社まで並列し、違いを 1 行添える。
  入れ替えは四半期ごとに `/go/` のクリック数と ASP の成果数を見て手で `rank` を変える

### 2. ASP の掲載規約はデータとして持ち、ビルド時に検査する

`affiliates.py` の `Asp`（広告表記の要否・`rel="sponsored"` の要否・計測 URL の許可ホスト・禁止表現）を
唯一の根拠として、`ad_check.py` が `dist` を検査する。1 件でも食い違えば配置しない。

1. 広告リンクを含むページに広告表記（`data-ad-notice`）がある
2. 広告表記が最初の広告リンクより前、かつ本文の冒頭 1,200 文字以内にある
   （A8 の「一般消費者が閲覧できる位置」＝ファーストビューで見えることの機械的な近似）
3. 広告リンクは `/go/<offer>/<placement>/` だけ。ASP ホストへの直リンクは転送ページ以外に無い
4. 広告リンクの `rel` に `sponsored` が入っている
5. 宣言した枠に実際にリンクが出ていて、転送ページが生成されている。未宣言の広告リンクが無い
6. `_redirects` の `/go/` の宛先ホストが ASP の許可ホストに一致する
7. 掲載ページに ASP の禁止表現が出ていない

飛び先 URL の制約（例: `https://aff.life-110.com/` 配下であること）はネットワークに出ないと
確かめられないため検査に含めず、登録時に人が 1 度だけ確認する手順にした（runbook 3）。

### 3. クリックは転送ページで数える

`/go/<offer>/<placement>/` を noindex の転送ページとして生成し、そこから計測 URL へ転送する。

- 計測ビーコン（Cloudflare Web Analytics）が 1 回動くので、**枠ごとにページ別の表示回数として
  クリック数が積み上がる**。`_redirects` の 302 ではページが読み込まれず何も数えられない
- 転送はビーコンの送信を見てから行う（先に離れると送られない。実測と待ち方は ADR 0011）。
  JavaScript が無効でもボタンで進める。sitemap には出さない
- 枠を含まない `/go/<offer>` の 302 は素の導線として `_redirects` に残す

## 影響

- 案件の受け渡しは `akiya-atlas-ops/docs/affiliates.md` の様式に固定する。掲載 URL の届け出一覧は
  `uv run akiya-atlas ad-urls` で出す
- クリック数が貯まるのは `CF_WEB_ANALYTICS_TOKEN` を入れてから（`docs/human-tasks.md` 6）。
  それまで導線と検査は動くが、数は取れない
- 転送ページの分だけ 1 ホップ増える。正確な件数を Cloudflare 側で取る必要が出たら、
  Pages Functions ＋ Analytics Engine に置き換える（そのときは転送ページを廃止できる）

## 追記: 「片付け」を種別として分けた（2026-09-13）

- 種別に `片付け` を足し、`owners-cleanup` は 片付け と 遺品整理 の 2 種別を受けるようにした
- 理由: 空き家の残置物撤去と遺品整理は、利用者にとって別のもの。空き家の所有者が求めるのは前者が多く、
  もしもの「空き家片付けセンター」を遺品整理として出すと、バッジの表示が実態と合わない
- **1 枠・1 種別・1 社は変えない**。両方の種別に案件があるときは、この枠に 1 件ずつ並ぶ
  （A8 の遺品整理の案件が承認されたらそうなる）
- 選定ツールの導線（`data/affiliates/profile.yaml`）も同じ 2 つに分けた。案件名に「遺品整理」があれば
  遺品整理、「片付け」「残置物」「不用品回収」があれば片付けに寄る
