# ADR 0011: 計測は Cloudflare RUM の自動挿入で行い、転送ページはビーコンを待つ

- ステータス: 採用（2026-09-12）
- 関連: ADR 0010（広告の掲載場所・規約の検査・クリックの計測）、sitemill ADR 0007

## 背景

Cloudflare Web Analytics を RUM の「自動挿入」モードで有効にした。この方式ではビーコントークンが
発行されず、Cloudflare が配信時に HTML へ計測タグを差し込む。sitemill は `CF_WEB_ANALYTICS_TOKEN` が
あるときだけタグを出す作りなので、トークン前提の設計（タグの出力・プライバシーポリシーの文面・
公開前チェック）と噛み合わない。また ADR 0010 の転送ページは読み込み完了の直後に転送するため、
ビーコンが送られる前に離れてクリックを取りこぼす恐れがあった。

## 確かめたこと（2026-09-12、本番で実測）

- 自動挿入は **apex（akiya-atlas.com）と pages.dev の両方**で効いている。`</body>` の直前に
  `type="module"` の `beacon.min.js` が差し込まれる。`noindex` かどうかは関係しない（HTML であれば入る）
  ので、**転送ページ `/go/<案件>/<枠>/` にも入る**
- ただし差し込まれるのはブラウザらしい要求のときだけ。User-Agent と Accept を付けない `curl` では入らない。
  ビルド成果物（`dist/`）には入らないので、`dist` を見る検査で確かめることはできない
- 送信のタイミング: `load` が 153 ミリ秒、`/cdn-cgi/rum` への送信開始が 295 ミリ秒（回線の速い環境で
  load の約 140 ミリ秒後）。**読み込み完了と同時に転送すると数えられない**
- Cookie は増えない。`Set-Cookie` は無く、`document.cookie` も空のまま

## 決定

1. **`CF_WEB_ANALYTICS_TOKEN` は設定しない**。入れると自動挿入のタグと合わせて 2 つ出て二重計測になる。
   `.env.example` と `docs/human-tasks.md` に「登録しない」と明記する
2. **プライバシーポリシーの記載はトークンではなくサイト側の事実で決める**。`pages.py` の
   `ANALYTICS_AUTO_INSERT` を `/about/` に渡し、トークンが無くても「Cloudflare Web Analytics を
   使用している／Cookie は使わない／集計される項目」を出す。トークンの有無で開示が消える状態をやめる
3. **転送ページはビーコンの送信を見てから転送する**。`PerformanceObserver` で `/cdn-cgi/rum` への
   通信を待ち、出たら 50 ミリ秒後に転送する。ビーコンが無い・遮られた環境のために上限 1.5 秒で打ち切る。
   実測どおりなら体感の待ちは 0.3 秒ほど
4. sitemill 側は変えない。`build/preflight.py` の「トークン未設定なのに解析タグがある」検査は
   `dist` を見るので、自動挿入とは衝突しない

## 代案（この方式で足りなくなったとき）

枠別のクリック数が取れない（自動挿入が止まる、広告ブロックの影響が大きい、正確な実数が要る）場合は、
Cloudflare Pages Functions で `/go/<案件>/<枠>` を受けて 302 しつつ Workers Analytics Engine に記録する。
サーバ側で数えるのでブラウザの事情に左右されず、転送ページも廃止できる。無料枠（1 日 10 万要求）で足りる。
代わりに Cloudflare 側のバインディング設定（人手）と実行コードが増えるため、必要になるまで採らない。

## 影響

- 転送ページの体感の待ちは 0.3 秒前後。JavaScript が無効なら自動転送されず、ボタンで進む（従来どおり）
- クリック数は Cloudflare Web Analytics の「ページ別の表示回数」で見る。`/go/<案件>/<枠>/` が
  枠ごとに別の行になる
- 自動挿入はブラウザらしい要求にだけ入るため、ビーコンが入っていることの確認は本番のブラウザで行う
  （`ad-check` は `dist` を見るので対象外）
