# ADR 0019: 公開前の歯止めで見る割合（掲載中でない物件・掲載中 0 件の巡回自治体・運営主体を判定できない自治体）

- ステータス: 採用（2026-09-29）
- 関連: sitemill ADR 0026（公開前の歯止め）・ADR 0028（読めた時刻で鮮度を進める）、ADR 0016、ADR 0018、
  `docs/data-issues.md` の 2026-09-28

## 背景

japan-open-today で、鮮度の測り方の誤りから本番の判定が 2 日間崩れた（sitemill ADR 0026）。
akiya-atlas でも、補助制度の確認日が抽出した日のままで、2027-03 に 2,638 件が一斉に「情報が古い
可能性」と出るところだった。テストと公開前の検査（ADR 0016）は、ページの形とコードの正しさを
見ていて、**結果の量**（掲載中の物件がどれだけ減ったか）は見ていない。

## 決定

sitemill v0.7.13 の `sitemill guard` を、ビルドと公開前の検査のあと、データのコミットの前に置く。
前回公開した値から急に悪くなっていたら**配置だけを止めて前日の本番を残し**、Issue（`publish-guard`）で
知らせる。データのコミットは止めない。見る割合としきい値は `service.PUBLISH_LIMITS`。

平常の値は、09-15〜09-29 の 15 晩の日次のデータ（各晩のコミットを取り出して数えた）。

| 指標 | 平常 | 1 晩の動き | 増え幅の上限 | 割合の上限 |
| --- | --- | --- | ---: | ---: |
| `listings_not_live` 掲載中でない物件（成約・掲載終了の可能性・退役） | 5.8〜6.2%（約 300 / 5,100 件） | 最大 0.2pt | +5pt | 置かない |
| `crawled_without_live` 物件一覧を巡回しているのに掲載中が 0 件の自治体 | 1.1〜1.9%（264 のうち 3〜5） | 1 自治体（0.4pt）まで | +3pt | 10% |
| `operator_undetermined` 運営主体を判定できない自治体 | 0%（1,742） | 0 | +1pt（17 件） | 3%（52 件） |

- **掲載中でない物件**: 鮮度・巡回・抽出の誤りで物件がまとめて古くなると上がる。データの始まりが
  09-10〜11 なので、売れた物件が 30 日で「掲載終了の可能性」になり始めるのは 10 月中旬からで、
  その後も 1 晩 0.4pt ほどの見込み。物件の多い県（福島 8.7%・北海道 6.3%・鹿児島 5.3%）の分が
  まとめて古くなれば +5pt を越える。割合そのものは売れた物件が溜まって月単位で上がっていくので、
  上限は置かない
- **掲載中 0 件の巡回自治体**: 物件の割合では、小さな自治体がまとめて 0 件になっても埋もれる。
  同じ作りの一覧（同じ CMS）の読み取りや巡回が壊れると、多くの自治体が同時に 0 件になる。
  物件の少ない県がまとめて止まった場合も、ここで止まる（8 自治体で +3pt）。10% は平常の約 5 倍
- **運営主体を判定できない自治体**: 公式サイトの解決（発見・heal・確かめ直し）が壊れたとき。
  確かめ直し（ADR 0018）で選び直した自治体が判定できずにレビューへ回ることはあるが、1 晩に数件

初回（基準の無い晩）は割合の上限だけを見る。09-29 のデータで数えると 5.8%・1.1%・0.0% で止まらない。

## 運用

- 止まったら、Issue のしきい値の文と実行の記録を見て原因を確かめる。データやコードの誤りなら直す
  （次の日次で通れば配置される）。正当な変化（自治体をまとめて足した・巡回の方針を変えた）なら、
  pipeline を手動実行して `accept_guard` を付け、今の値を基準にする
- 基準は `data/state/publish_guard.json`。検査を通った回（と受け入れた回）だけ更新され、日次の
  コミットに入る。deploy-only の実行でも、通れば基準だけをコミットする

## 採らなかった案

- **物件の件数で比べる**: 自治体を足した晩は、増えた分がそのまま悪化に見える（sitemill ADR 0026 と同じ）
- **補助制度の「情報が古い可能性」の割合**: 確認日を読めた日で進めるようにした（09-28）直後で、
  平常の幅がまだ測れていない。数週間たまってから足すかを決める
