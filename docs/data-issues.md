# データの取り違えの記録

本番のデータで見つかった取り違えと、その原因、いまそれを防いでいる仕組みを残す。
他県に展開するとき・自治体を選び直すときは、末尾の「検査項目」を当てる。新しいものを上に書く。

## 2026-09-17 公式サイトの取り違え（同じ読みの別の自治体）

### 何が起きていたか

7 自治体が、**同じ読みの別の自治体の公式サイト**を自分の公式サイトとして載せていた。
採用していたページには、その自治体の名前が 1 回も出ていなかった。

| 自治体 | 採用していたホスト | 実際の持ち主 | そのページに自分の名前 | 直した公式サイト（県の一覧） | 直したあとの空き家バンク |
|---|---|---|---|---|---|
| 長崎県対馬市 | www.city.tsushima.lg.jp | 愛知県津島市 | 0 回 | www.city.tsushima.nagasaki.jp | 巡回（物件 12 件） |
| 滋賀県湖南市 | www.city.konan.lg.jp | 愛知県江南市 | 0 回 | www.city.shiga-konan.lg.jp | 見つからない |
| 高知県香南市 | www.city.konan.lg.jp | 愛知県江南市 | 0 回 | www.city.kochi-konan.lg.jp | 巡回（物件 1 件） |
| 栃木県さくら市 | www.city.sakura.lg.jp | 千葉県佐倉市 | 0 回 | www.city.tochigi-sakura.lg.jp | 制度案内 |
| 福井県坂井市 | www.city.sakai.lg.jp | 大阪府堺市 | 0 回 | www.city.fukui-sakai.lg.jp | 制度案内 |
| 高知県津野町 | www.town.tsuno.lg.jp | 宮崎県都農町 | 0 回 | town.kochi-tsuno.lg.jp | 巡回（物件 2 件） |
| 山梨県中央市 | www.city.chuo.lg.jp | 東京都中央区 | 0 回 | www.city.chuo.yamanashi.jp | 見つからない |

持ち主は、各ホストのトップページを 1 回ずつ取得し、題名と自治体名の出現回数で確かめた。

**利用者への影響**

- 市町村ページの「〇〇市の空き家バンク（公式）を見る」が、別の自治体のサイトを開いていた。利用者が問い合わせる窓口を間違える
- `/data/<県>/` の「根拠」に、別の自治体のドメインが自治体の根拠として出ていた
- 空き家バンクの状態（制度案内・見つからない）も、別の自治体のサイトから判定していた。直したら対馬市・香南市・津野町は物件が取れるバンクだった
- 対馬市と中央市は、別の自治体の補助金ページを巡回対象にしていた。制度の記録は持ち主（津島市・中央区）の側に付いていたので、制度の誤表示は無かった（直したあとも持ち主の件数は変わらず、2 つの自治体に付いた制度は全国で 0 件）
- 物件の巡回には影響していなかった

**見つけた経緯**: japan-open-today で「運営主体の判定が、どの規則にも当たらないと既定で施設の公式を返す」問題が
見つかり、akiya-atlas に同じことが無いか調べた。既定値は無かった（判定できなければ `pending`）が、公式サイトの
ホストを全国で突き合わせたら、6 つのホストを 13 自治体が指していた。

### 原因

1. 読みから推測した `.lg.jp`（県の区切りの無い形）を、県の市町村一覧より先に試していた
2. 推測で当たったサイトが、その自治体のものかを確かめていなかった（「URL を推測で組み立てない」原則の違反）
3. 同じサイトを複数の自治体が指していないかの点検（`_flag_shared_official_urls`）が、県ごとの発見の中でしか効いていなかった。県をまたぐ同じ読みは素通りした

**「県の一覧を先に使う」にしなかった理由**: 推測で決めた 1,446 件のうち、県の一覧と食い違うのは 46 件で、
その多くは一覧のほうが古い（旧ドメイン）。順番を入れ替えると、いま正しい自治体が崩れる。

### 直したこと

- 9 自治体（上の 7 件と下の 2 件）を `data/reference/municipal_overrides.json` で県の一覧の URL に固定し
  （`evidence` は画面に出る根拠、`note` に経緯）、選び直した（`6335488`、`6a10a49`）。補助金のページは
  `subsidy-pages --code` でその自治体だけ取り直した
- **推測したサイトは、自治体名がページに出るときだけ採用する**（`b70fcf8`、`expand.page_names_municipality`）。
  全角半角と「ヶ・ケ」を吸収して比べる。heal が前回のホストを使い回すときも同じ確認をする。
  採用済みの 150 件を抜き取って確かめたところ、名前が出なかったのは土佐市の 1 件だけで、ボット対策の拒否画面だった
  （県の一覧も同じホストなので、結果は変わらない）
- **公開直前の検査に 2 つの性質を足した**（`b965142`、ADR 0016 の性質 5 と 2）
  - 公式サイト（ホスト、`www.` の有無は同じ扱い）を 2 つの自治体が指していない（全国で）。同じ漢字の同名
    （伊達市・府中市・池田町など）は名前の確認では見分けられないので、ここで止める
  - `municipal_overrides.json` で固定した公式サイトを指している（選び直しで元に戻っていない）

正しかった。2 件は次のとおりで、同じ方法で直した。

## 他県に展開する・自治体を選び直すときの検査項目

1. `uv run akiya-atlas publish-check` が通る（公式サイトの重複・固定した扱いを含む）
2. 推測で採用した公式サイトに、その自治体の名前が出ている（発見と heal が自動で確かめる。ログに
   「推測した … に市町村名が出ないので使わない」と出たら、県の一覧に落ちている）
3. 推測と県の一覧が食い違う自治体は、両方のトップページを開いて題名を見る。今回は 46 件中 9 件が、別の自治体か
   使えないリンクだった
4. 同じ漢字の同名は名前の確認をすり抜ける。重複の検査で止まったら、県の一覧で持ち主を決め、
   `municipal_overrides.json` に根拠つきで固定する
