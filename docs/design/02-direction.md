# 02. 方向性

## コンセプト
**「役所の掲示板の信頼感 × 地図帳（アトラス）の分かりやすさ」**。
派手さより「数字と地図で状況が一目で分かり、公式ページへ迷わず進める」ことを優先する。
色は紙（生成り）と深緑と柿渋。写真が無くても成立するよう、数字・地図・図解・アイコンで視覚要素を作る。

## 配色（すべて CSS 変数で統一。汎用の青・紫グラデーション・絵文字は使わない）
コントラストは WCAG の値（計算済み）。本文は 7:1 以上、補助テキストと大きな数字は 4.5:1 以上、UI 部品は 3:1 以上。

## 書体
- **BIZ UDPGothic**（モリサワのユニバーサルデザイン書体、Google Fonts、ウェイト 400/700）。年配の利用者向けに文字の判別性が高く、数字も読みやすい。
  `<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>` + `display=swap`。フォールバックは
  `"BIZ UDPGothic", "Hiragino Sans", "Meiryo", "Yu Gothic UI", system-ui, sans-serif`（Windows で細く出る Yu Gothic より Meiryo を先に）。
- 計測: 実装後に Lighthouse（モバイル）で LCP と CLS を before と比べる。**LCP が 0.5 秒以上悪化、または CLS が 0.1 を超えたら**、
  見出しと数字だけ Web フォントにし、本文はシステムフォントに後退する。それでも悪ければ Web フォントをやめる。
- 文字サイズ: 本文 18px（≥ 60rem で 19px）、行間 1.85。補助テキストも 16px 未満にしない。見出し H1 1.75rem / H2 1.35rem（太字、行間 1.35、`text-wrap: balance`）。
  数字は 2.25〜3rem の太字、`font-variant-numeric: tabular-nums`。単位は小さく添える。
- タップ領域は 44px 以上。リンクは下線付きの濃色（色だけに頼らない）。外部リンクにはアイコンと「外部」の文言。

## レイアウト
- **1 カラム基調**。最大幅 72rem。ページ背景は生成り、内容ブロックは白い面。面の使い分けで区切り、罫線は最小限。
- **数字の帯（stat strip）を H1 の直下に全ページ共通で置く**。件数・価格帯・築年・補助金など、そのページで一番知りたい数字を 3〜5 個。
  帯の中に「ミニ分布」（価格帯 7 区分の小さな棒）を入れ、詳しいヒストグラムは下のセクションに置く。
- **一次情報リンクは常に主ボタン**（深緑・白字・外部アイコン・「公式」の明記）。物件ページではファーストビューに入れる。
- **表よりカード**。スマホで 1 列、PC で 2〜3 列。列の多い表は「主要 3 列 + 折りたたみ」か、カードに置き換える。
  ただし補助制度の一覧と、地図の代替（市町村一覧）は表として残す（スクリーンリーダーと比較のため）。
- ヘッダー: ロゴマーク（自作 SVG。家の輪郭の中に等高線＝地図帳の記号）+ サイト名 + 3 リンク。スマホでは横スクロールせず 2 段。
- 余白スケール: 4 / 8 / 12 / 16 / 24 / 32 / 48px。セクション間 48px（スマホ 40px）。

## 部品（templates/partials/ にマクロ化）
| 部品 | 役割 | 備考 |
|---|---|---|
| `stat_strip(items)` | 数字の帯 | 値・単位・ラベル・補足。値が無い項目は「—」ではなく非表示 |
| `mini_bars(bins)` | 価格帯/築年のミニ分布 | インライン SVG、`role="img"` と表の代替 |
| `listing_card(row)` | 物件カード | 価格（大）、タイトル、所在地、面積・築年・間取り、バッジ、確認日、写真枠 |
| `muni_card(row)` | 市町村カード | 名前、件数（大）、売買/賃貸、補助金バッジ、最終取得 |
| `badge(kind, text)` | バッジ | `ok`（補助金あり）/ `info`（詳細あり）/ `warn`（掲載終了の可能性・値下げ）/ `mute`（成約済） |
| `primary_link(url, label)` | 一次情報の主ボタン | 外部アイコン、`rel="noopener"`、`target="_blank"` |
| `section_head(title, note)` | 見出し + 補足 | 番号は付けない（順序に意味が無い） |
| `status_card(muni)` | 非巡回市町村の状態説明 | 登録制／公式ページのみ／民間のみ／未対応の 4 状態を文章で説明 |
| `photo_slot()` | 将来の写真枠 | 写真データが無い間は DOM に出さない（`{% if photo %}`）。カードと物件ページに置き場所だけ決める |
| `icon(name)` | インライン SVG アイコン | 家・円・面積・築年・間取り・補助金・外部リンク・確認・地図ピン・注意。`templates/partials/icons.svg` のスプライトを `<use>` |
| 信頼ブロック | sitemill のマクロをそのまま使う | 見た目だけ CSS で整える（2 列グリッド、最終更新を大きく）。`data-sitemill-trust` は維持 |

## 視覚要素
### 都道府県ページの地図（市町村別の件数を色分け）
- **データ**: 国土交通省 国土数値情報 行政区域データ N03（2025 年版）。個別ページの「使用許諾条件」は **オープンデータ（CC BY 4.0）**で、
  sitemill のライセンス判定ホワイトリスト（`license/detector.py`: CC BY 4.0 / 3.0 / 2.1 JP、CC0、政府標準利用規約 2.0）に含まれる。
  出典表記: 「出典: 国土交通省 国土数値情報ダウンロードサイト（行政区域データ N03、2025 年）を加工して作成」を地図の直下と /data/ に記載する。
  注意: 同ページには「本データを二次利用する場合には、国土地理院に申請等必要な場合があります」（測量法の複製・使用承認）の注記がある。
  本サイトの用途は市町村単位の簡略化した輪郭図（測量成果としての精度を持たない図解）だが、この注記は記録し、承認時に判断してもらう。
- **生成手順**（実装時。リポジトリには生成物の SVG だけを入れる）: zip 取得 → `N03-20250101_<県コード>.geojson` → `npx mapshaper` で
  `-dissolve N03_007`（市区町村コードで結合）→ `-simplify 4% keep-shapes` → `-proj webmercator` → `-o format=svg id-field=N03_007`。
  1 県 30〜80KB を見込む。`templates/maps/<slug>.svg` に置き、都道府県テンプレートから `{% include %}` でインライン化する。
- **色付け**: Jinja で `municipalities` 行の `code[:5]`（6 桁コードの検査数字を除く）と SVG の `id` を結合し、件数から段階クラスを付ける。
  各市町村は `<a href>` で市町村ページへ、`<title>` に「東御市 70 件」。凡例と「地図は簡略化しています」の注記。
  非巡回市町村は白＋灰の縁、0 件は斜線。**地図の代替**として市町村一覧（表）を必ず残す。
- **代替案 B（地理データを使わない）**: 市町村を郡・地域ごとの升目に並べて色分けするタイル図。位置関係は粗いがライセンスの論点が無い。
- 記録: `docs/design/map-data-license.md`（実装時に作成。取得日・ファイル名・ハッシュ・簡略化率・出典表記を書く）。

### ヒストグラム（価格・築年）
- sitemill.charts の `column_chart` をそのまま使い、CSS 変数（`--chart-series-1` 等）を本サイトの色に合わせる。
  `base.html` で `chart_css` の `<style>` を `style.css` より前に置き、`style.css` 側で上書きできるようにする。
- 数字の帯の「ミニ分布」は Jinja でその場で描く（`selectattr` で区分ごとの件数を数え、SVG の `rect` を並べる）。データ点が少ない
  （既存の `MIN_CHART_POINTS` 未満）ときは棒ではなく「価格帯: 300〜500 万円が最多」のような 1 文にする。

### 所有者向けのフロー図
- 「相続した空き家の選択肢」: 分岐図（住む／貸す／売る／自治体の空き家バンクに登録／解体して土地を活用／当面は管理）。各枝に
  「向いている場合」「最初の一歩」「関係する補助」を短く。`templates/partials/flow_options.svg` に手書きの SVG（コード生成）として置き、
  `data-generated` と「自動生成の図解」の注記を付ける。文章版を `<details>` で併記する（既存のフロー図と同じ流儀）。
- 「査定・解体の流れ」: 既存の `flow_diagram` を使い、CSS で箱を大きく（文字 16px 以上）。sitemill 側の改善は 04 に提案。

### アイコン・ロゴ・写真枠
- アイコンは自作の線画 SVG スプライト（24px グリッド、線幅 2）。絵文字は使わない。
- ロゴマーク: 家の輪郭と等高線を組み合わせた単色マーク（SVG、`static/logo.svg` と favicon）。
- 写真枠: 将来ライセンス確認済みの写真を差し込めるよう、カードと物件ページに `photo_slot` の置き場所を決める。データが無い間は出力しない
  （空の枠や「写真なし」の板を並べない）。実在の場所・物件を描いた画像は使わない。

## アクセシビリティ
- 色だけに意味を持たせない（バッジは文言＋アイコン、地図は数値ラベルと表）。フォーカスリングを可視化（2px、`--kaki`）。
- 見出し階層を守る。地図・図解は `role="img"` + `<title>`/`<desc>`、表の代替を併記。
- `prefers-reduced-motion` を尊重（そもそもアニメーションは使わない）。

## 性能
- 追加 JS なし。`search.js` は結果をカード描画にする改修のみ（依存ライブラリなし）。
- インライン SVG（地図 30〜80KB、アイコン 3KB）。CSS は 1 ファイル 20KB 以下を目安。
- Web フォントは上記の計測と撤退基準に従う。画像は使わない。
- Google Maps の埋め込みはキー未設定時のフォールバック（外部リンク）を維持し、リンクをカード状の主導線にする。

## 実装計画（承認後）
1. `static/style.css` を書き直す（トークン → 基本 → 部品 → ページ）。`static/search.js` の描画をカードに。
2. `templates/partials/`（macros.html, icons.svg, flow_options.svg）と `templates/maps/*.svg` を追加。
3. `base.html`（ヘッダー・フッター・フォント読み込み・theme-color）→ `index` → `prefecture` → `municipality` → `listing` → `owners` → `about` / `data` / `404`。
4. 検査: scratchpad の作業ツリーで `uv run sitemill build`（crawl / extract は走らせない）と `uv run pytest`。全検査を通す。
5. before/after のスクリーンショット（375px / 1440px）と Lighthouse を並べて報告。
