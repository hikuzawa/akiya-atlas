# サイトデザインの見直し（2026-09）

現状のサイトは「見出し・本文・罫線表」だけの文書レイアウトで、ブランド要素が無く、いかにも機械生成に見える。
主役の利用者（相続した空き家に悩む 40〜60 代、スマホ閲覧）と移住検討者が、数字と図で直感的に状況を掴め、
一次情報へ迷わず進める、視覚的に信頼できるサイトへ作り直す。

## 制約（作業分担）
- このセッションが触るのは `templates/`、静的アセット（`static/` の CSS・JS・SVG）、`docs/design/` だけ。
- sitemill（図解モジュール等）と `src/akiya_atlas/`（発見・巡回・抽出・ページ生成）、`data/` は本線セッションの担当。必要な変更は 04 に提案として書く。
- ビルド時検査（信頼シグナル `data-sitemill-trust`・canonical・OGP・JSON-LD・PII・番地・公開 URL）はすべて通す。信頼ブロック（更新日時・一次情報リンク・運営者・件数）は必須要素として残す。
- 静的サイトのまま。JS は検索フィルタなど必要最小限。写真は載せない（将来のための枠だけ用意）。実在の場所や物件を AI 画像で描かない。図解は SVG のコード生成に限り「自動生成」と明記する。

## 進め方
1. 監査 → 方向性 → ワイヤーフレーム（このドキュメント群）→ **承認**
2. 実装（templates / static）→ ローカルビルドで全検査を通す → before/after のスクリーンショット（モバイル幅・デスクトップ幅）→ Lighthouse の比較 → コミット

## 承認時に決めてほしいこと
1. 方向性（02）: 配色「深緑 × 生成り × 柿渋」、書体 BIZ UDPGothic（Web フォント。計測して重ければ見出しのみ／システムフォントに後退）、数字の帯を全ページ上部に置く構成。
2. 都道府県ページの市町村地図（02 の「地図」）: 国土数値情報 行政区域データ N03（CC BY 4.0、ホワイトリスト内）を使う案 A と、地理データを使わないタイル図（市町村を升目に並べて色分け）の案 B。A を推奨。A の場合、長野（6.6MB）・香川（4.4MB）・沖縄（15MB）の zip を国土交通省サイトから取得し、`npx mapshaper` で簡略化して SVG にする（作業用の取得で、リポジトリに入るのは数十 KB の SVG だけ）。
3. 計測に `npx lighthouse`（Chrome を使う CLI、初回に npm から取得）を使ってよいか。
4. 物件カードの「詳細あり」バッジ: 今の出力データには「詳細ページから抽出したか」の印が無い。04 の提案（`has_detail`）が入るまでは「築年・面積あり」など事実に基づく表記にする（承認後に本線へ依頼）。
